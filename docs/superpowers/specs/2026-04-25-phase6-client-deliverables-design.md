# Phase 6 Design Spec: Client Deliverables

PDF compliance reports, compliance badges, and shareable client dashboards.

## Design Decisions

| # | Decision | Choice |
|---|----------|--------|
| 1 | PDF template strategy | Single branded template for all tiers. Starter gets default branding, Agency/Pro get custom logo + brand color. VPAT included from day one (Pro-only). |
| 2 | PDF generation library | `@react-pdf/renderer` — React JSX components, `renderToBuffer()` in Next.js API routes. |
| 3 | Compliance badge format | Dynamic SVG endpoint (`/api/badge/[siteId]`). Shields.io style, real-time score, 1hr cache. |
| 4 | Shareable dashboard scope | Both snapshot (frozen scan) and live (current site state). Agency chooses when creating link. |
| 5 | Share link access control | Configurable expiration (7d / 30d / 90d / never) + manual revoke. No password. |
| 6 | UI entry points | "Deliverables" tab on site detail page + download PDF icon on each scan history row. |
| 7 | PDF report content | Comprehensive + before/after comparison (cover, executive summary, score delta, page-by-page, violations with AI fixes, WCAG mapping, glossary). |
| 8 | VPAT generation | Auto-fill from axe-core results + manual override review step before download. |
| 9 | VPAT review UI | Dedicated `/sites/[siteId]/vpat` page with editable criteria table, auto-save, progress indicator. |

## Tier Gating

| Feature | Starter | Agency | Pro |
|---------|---------|--------|-----|

## 1. Database Schema

### `reports` table

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID PK | Primary key |
| siteId | UUID FK -> sites | Which site |
| scanId | UUID FK -> scans (nullable) | Null for live share links |
| organizationId | text FK -> organization | Owning org |
| type | enum: `pdf`, `vpat`, `share_snapshot`, `share_live` | Deliverable type |
| storageUrl | text (nullable) | Vercel Blob URL for generated PDFs |
| shareToken | text (unique, nullable) | Public access token for share links |
| expiresAt | timestamp (nullable) | Null = never expires |
| metadata | JSONB (nullable) | Flexible storage (e.g., VPAT product info overrides) |
| createdAt | timestamp | Created |
| updatedAt | timestamp | Last updated |

### `vpatEntries` table

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID PK | Primary key |
| reportId | UUID FK -> reports | Which VPAT report |
| criterionId | text | WCAG criterion (e.g., "1.1.1") |
| level | text | "A" or "AA" |
| conformanceLevel | enum: supports, partially_supports, does_not_support, not_applicable, not_evaluated | Conformance status |
| remarks | text (nullable) | Agency's notes |
| autoDetected | boolean | Was this auto-filled by axe-core mapping? |
| updatedAt | timestamp | Track edits |

## 2. PDF Compliance Report

### Generation flow

1. User clicks download icon on scan history row or "Generate Report" in Deliverables tab.
2. Next.js API route `POST /api/reports/generate-pdf` receives `{ scanId }`.
3. Queries: scan + violations + pages + site + org (branding) + previous scan (for comparison).
4. Renders via `@react-pdf/renderer` `renderToBuffer()`.
5. Returns PDF as stream response (`Content-Type: application/pdf`).
6. Creates a `reports` row (type: `pdf`) with optional Vercel Blob storage URL.

### PDF sections

1. **Cover page** — Agency logo, brand color accent, site URL, scan date, compliance score (large), "Accessibility Compliance Report" title.
2. **Executive summary** — Overall score, pass/fail counts by severity (critical/serious/moderate/minor), total pages scanned, scan duration.
3. **Score comparison** — Current vs previous scan: score delta, new violations, resolved violations, regression count. Shows "First scan — no prior data" if no previous scan.
4. **Page-by-page breakdown** — Table of each crawled URL with individual score and violation counts.
5. **Violations by severity** — Grouped tables (Critical -> Minor). Each violation: rule, WCAG criteria, page URL, description, HTML snippet, AI explanation, AI fix code.
6. **WCAG criteria mapping** — Table of all tested WCAG 2.1 AA criteria with pass/fail status.
7. **Glossary** — "What these scores mean" for non-technical clients: WCAG levels, severity ratings, compliance scoring methodology.
8. **Footer** — "Generated by AccessAudit on [date]" with agency branding.

### Branding

- **Starter**: AccessAudit default logo and indigo (#6366f1) accent color.
- **Agency/Pro**: Org's uploaded logo and `brandColor` from `organizationSettings`.

## 3. VPAT Generation & Review (Pro Only)

### Auto-fill logic

Map axe-core violation results to WCAG 2.1 AA success criteria:

- Zero violations for criterion -> **Supports**
- Some violations found -> **Partially Supports**
- High violation count (5+) -> **Does Not Support**
- Criterion not testable by axe-core -> **Not Evaluated** (highlighted for manual review)

Axe-core covers ~57 of 78 WCAG 2.1 AA criteria. Remaining ~21 are marked "Not Evaluated."

### Generation flow

1. User clicks "Generate VPAT" in Deliverables tab.
2. System creates `reports` row (type: `vpat`) + 78 `vpatEntries` rows (auto-filled where possible).
3. Redirects to `/sites/[siteId]/vpat` review page.

### Review page (`/sites/[siteId]/vpat`)

- **Product info header**: Pre-filled from org + site data (product name, report date, contact email). Editable.
- **Criteria table**: Filterable by level (A / AA), sortable by conformance status.
- **Each row**: Criterion ID + name, conformance dropdown, remarks textarea, "Auto-detected" badge.
- **Highlighted rows**: "Not Evaluated" criteria highlighted in amber — prompts manual review.
- **Progress indicator**: "42/78 criteria reviewed" counter.
- **Auto-save**: Debounced save on each field edit.
- **Actions**: "Download VPAT PDF" button, "Reset to Auto-Detected" button.

### VPAT PDF structure (ITI VPAT 2.5 WCAG edition)

- Page 1: Product information (name, version, date, description, contact, evaluation methods).
- Page 2+: Success criteria tables — Level A, then Level AA — each with Criteria, Conformance Level, Remarks columns.

## 4. Compliance Badge (Dynamic SVG)

### Endpoint

`GET /api/badge/[siteId]`

### Behavior

1. Validates site exists and org plan is Agency+.
2. Queries latest completed scan for that site.
3. Returns SVG with `Content-Type: image/svg+xml`, `Cache-Control: public, max-age=3600`.

### Badge design

- Left segment: "WCAG 2.1 AA" label on dark background.
- Right segment: Score with color coding — green (>=90%), yellow (>=70%), red (<70%).
- Shields.io flat style. Example: `[WCAG 2.1 AA | 94% Compliant]`.

### Access control

- Public endpoint (no auth) — designed for embedding on client sites.
- Returns data only if org plan is Agency+ and site has a completed scan.
- Returns generic "Not Available" badge if conditions not met.

### Embed code (shown in Deliverables tab)

```html
<a href="https://accessaudit.com/share/{shareToken}">
  <img src="https://accessaudit.com/api/badge/{siteId}" alt="Accessibility Score" />
</a>
```

## 5. Shareable Client Dashboard

### Route

`/share/[shareToken]` — public, no auth required.

### Access flow

1. Middleware allows `/share` path without auth.
2. Page queries `reports` table by `shareToken`.
3. Checks `expiresAt` — if expired, shows "This report has expired. Contact your agency for an updated link."
4. Routes to snapshot or live view based on `type` field.

### Snapshot view (type: `share_snapshot`)

Tied to a specific scan. Shows:
- Compliance score + scan date
- Violation summary by severity
- Page-by-page breakdown table
- Violations list with AI explanations and fix code
- "Download PDF" button (generates on-the-fly)

Data is frozen — always shows that specific scan's results.

### Live view (type: `share_live`)

Tied to a site. Shows:
- Current compliance score + trend chart (last 10 scans)
- Latest scan's violation breakdown
- Page-by-page scores from most recent scan
- Auto-updates as new scans complete

### Shared UI

- Agency branding (logo + brand color) in header.
- "Powered by AccessAudit" subtle footer link.
- No navigation, no edit controls — purely read-only.
- Responsive design for mobile viewing.

### Creating share links (Deliverables tab)

- "Share Scan" button -> pick scan -> choose expiration (7d / 30d / 90d / Never) -> generates snapshot link.
- "Share Live Dashboard" button -> choose expiration -> generates live link.
- Table of active share links: type, created date, expires, copy URL button, revoke button.

## 6. UI Integration Points

### Site detail page — new "Deliverables" tab

Contains three sections:
1. **Reports**: Generate PDF button, list of previously generated PDFs with download links.
2. **Badge**: Live preview of SVG badge, copy embed code button. Shows upgrade prompt for Starter.
3. **Share Links**: Create snapshot/live links, manage existing links table (copy, revoke).
4. **VPAT**: Generate VPAT button (Pro) or upgrade prompt. Link to review page if VPAT exists.

### Scan history table — download button

Each completed scan row gets a download icon button (FileDown icon). Clicking triggers PDF generation and download for that specific scan.
